# Computer History 主动待办建议

开启 Computer History 记录后，「主动建议」使用同一次活动理解请求生成 History 和待办判断。
建议不会直接创建待办。用户确认或修改后，桌面端将它写入 macOS「提醒事项」当前默认清单。

## 体验

1. 启动 Electron 开发版，进入「记忆管理 → Computer History」，开启记录和主动建议。
2. 正常使用应用。模型从最近的活动判断是否有明确、未处理的个人事项。
3. Memmy 在前台时显示轻提示卡片；在后台时发送静默系统通知，点击后打开同一张卡片。
4. 可以编辑标题与提醒时间、稍后处理或忽略。未指定明确时间的事项不会擅自设置闹钟。
5. 点击「添加到提醒事项」才执行原生写入。首次使用可能需要 macOS 自动化授权。
6. 添加成功后显示实际清单名称，并提供「打开提醒事项」。任务的修改和完成在提醒事项中进行。

没有出现建议可能是模型判断当前无需打扰，而不是录制或服务失效；页面单独展示分析状态和错误。
本版本不含听记建议，也不会自动录音。

## 功能介绍与主动询问

首次进入 Computer History 会显示功能介绍，也可以点击标题旁的 `i` 再次打开。
弹窗分别设置「记录电脑活动」和「Memmy 主动提醒」。开关先保存在弹窗草稿中，确认后才生效；
关闭弹窗不改变服务。录制开启会等待采集器真正就绪，失败或尚未就绪时可以留在弹窗重试。
停止记录会保留主动提醒的偏好，下一次开始记录后再生效。关闭应用仍会停止本次录制。

用户可以直接在普通对话中问「我刚才在忙什么」「刚才看的网页在哪」。Agent 会按描述选读
内置 `computer-history` skill，然后检查录制状态、当前时间和时区，读取相关摘要或原始事件回答。
询问本身不会开启录制、创建待办或操作桌面。

History 页的「询问活动」会把问题放入普通对话输入框，用户编辑后再发送；已有草稿与附件保留。
技能入口为 `App/memmy-agent/src/skills/computer-history/SKILL.md`，随构建复制至运行时。

## 触发与状态

- 默认每 30 秒检查新增活动；没有新证据或已有一次分析在运行时不重复请求。
- 模型输出 `now`、`later` 或 `none`。`later` 等后续新活动重评，不直接变成定时弹窗。
- 引用必须对应保留的语义原文；按下 Return、字符数量或事件字段名不能成为待办证据。
- 自动出现的建议有效期为 3 分钟，过时后需重新判断；建议记录最多可供手动查看 1 小时。
- 自动提示间隔至少 10 分钟，滚动 24 小时最多 6 次。用户「稍后」的等待时间为 10 分钟。
- 自动卡片 30 秒无交互会收起；悬停、编辑、添加中、失败或成功回执时保留。
- 忽略、已添加和待处理记录会提供给后续判断；同一原文或同一事项也做本地去重。
- 暂停记录、关闭主动建议或旧模型请求迟到时不会生成新的提示。
- 建议与反馈保存在 `~/.memmy/computer-history/proactive-reminders.json`，保留最多 48 小时。

## 开发与验证

首次安装依赖后先构建共享接口，再启动开发桌面：

```sh
npm ci
npm --prefix App/memmy-agent ci
npm run build -w @memmy/local-api-contracts
npm run dev:desktop
```

macOS 开发启动的 `predev` 会补齐本仓库 Electron 的 Automation 用途说明。它只修改本地开发依赖，
不修改系统权限或安装版 Memmy。打包配置也包含对应声明。

模型判定、证据过滤、时效/去重、HTTP 鉴权、前后端契约、卡片交互和原生序列化均有测试。
原生写入使用固定 JXA 程序，数据通过 JSON 参数传递，重试通过持久标记核验已有提醒。
单元测试不操作用户的提醒事项。真实系统联调应使用可识别的临时测试项，并在验证后完成它。
