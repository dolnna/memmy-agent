# 记忆回顾：从新对话开始

新对话输入框下只保留一行「记忆回顾 · 今日 · 本周 · 自定义」。点击今日/本周直接把完整 Prompt 带进原输入框；自定义只打开一个时间输入小浮层。用户修改并发送后，回复进入原有对话，历史只从原任务列表和搜索打开。

直接引用现有 `HomePage`，由它渲染原有 `AppFrame`、输入框、模型选择器和 `AgentThreadMessages`。这些原有 UI 文件及样式保持原样。`recap-preview-mount.tsx` 仅在 DEV 预览外围把入口挂到原输入框下，并让原侧栏和搜索打开本地回顾对话。首页卸载/重建时重新挂载入口，回顾的发送范围绑定到对应草稿；这是独立预览适配，不是正式业务接线。

## 预览

```sh
npm run preview:weekly -w @memmy/frontend-desktop
```

打开 `http://127.0.0.1:19030/?preview=memory-weekly`。
预览仅监听本机，禁用热刷新、Analytics 初始化和应用 API 代理。添加 `&data=memmy` 后，生成按钮通过预览专用本地接口调用当前配置的 Memmy Agent，并会消耗对应模型额度。记忆快照路径由 `MEMMY_WEEKLY_PREVIEW_REPORT_PATH` 定位，私人记录和生成原文不进入仓库。

## 交互边界

- 今日、本周直接预填；自定义支持昨日、本月、最近 N 天/周和明确日期范围，按本地日历解析并显示绝对日期。
- 完整 Prompt 在原有新任务输入框里展示、修改，点击原有发送按钮才授权并发起该次模型调用；选择时间不调用模型。
- 新任务、空输入不会误用之前的回顾时间；已准备的时间和发送消耗在输入框下说明。
- 每次生成独立保存，即便时间范围相同也保留旧版。
- 历史按生成时间倒序保留，只从原侧栏和原搜索打开。刷新后仍可打开，已保存回顾的追问草稿也保留。
- 上一版首页卡已保存的回顾会导入新档案，原缓存不删除。
- 保存失败时明确提示未保存并提供重试，不假称成功。
- 仅在当前浏览器 localStorage 保存；真实/示例和 `recapPreviewSession` 隔离，旧记录不随日期变化覆盖。
- `data=memmy` 会按所选记录日期筛选私人快照，再运行一次隔离的 Memmy Agent；没有记录时不调用模型。配置副本、工作目录和 Session DAG 全部写入独立私有目录，Memory Hook、MCP 工具和 DAG 均关闭，正式配置在生成前后做哈希校验。
- 预览没有应用 API clients；沿用原生输入框，后续对话发送仍禁用，但可以输入并保存追问草稿。

正式后端的实时记忆检索、账户隔离和跨设备保存、真实对话发送尚未接入。主动洞察和自动任务接续不在本轮范围。

验证覆盖：本地日期边界、多次同范围生成保存、损坏缓存保护、原文注入真实 appReducer、普通草稿/回顾草稿切换，以及浏览器实际交互。旧 `weekly-home-card` / `weekly-home.css` / `recap-popover` 是前几轮原型，当前入口不再引用。
